## 1. 心智模型：谁生成什么，谁改什么

```
design.modus  ──[Device Configurator]──►  GeneratedSource/cycfg_*.c/h
（GUI 专有格式）                            （配置结构体 + 引脚宏 + 路由）
                                                    │
                                                    ▼
                                         你的代码调 Cy_*_Init / mtb_hal_*_setup
```

| 文件 | 角色 | 谁改 |
| --- | --- | --- |
| `bsps/TARGET_CYT2BL3/config/design.modus` | 硬件设计：引脚、外设、时钟、电源 | **只能** Device Configurator GUI |
| `bsps/TARGET_CYT2BL3/config/GeneratedSource/*` | 上者的 C 代码产物 | 自动生成，**禁止手改** |
| `bsps/TARGET_CYT2BL3/cybsp.c/h` | 板级初始化 `cybsp_init()` | 不改 |
| `Makefile` | 工程配置（名字、器件、配置、组件） | 手改 |
| `main.c` / 自己的 `source/*.c` | 应用逻辑 | 手改 |

**核心铁律**：配置出问题，回 Device Configurator 改，**不要在代码里用 `Cy_SysClk_*SetDivider()` / `Cy_GPIO_SetHSIOM()` 绕过**。绕过会与生成的配置打架，且下次生成时被覆盖。

## 2. 引脚规划（配 DC 之前必须先做）

### 2.1 复用表在哪

不需要联网查手册，PDL 器件头里就有完整的 HSIOM 枚举：

```
mtb_shared/mtb-pdl-cat1/release-v3.25.0/devices/COMPONENT_CAT1A/include/
└── gpio_tviibe4m_64_lqfp.h        ← CYT2BL3CAS 实际用的就是这个（cyt2bl3cas.h:650 include）
```

里面的 `en_hsiom_sel_t` 枚举列出每个引脚**全部**可选功能：

```c
P0_0_GPIO                 =  0,   /* GPIO controls 'out' */
P0_0_TCPWM0_LINE18        =  8,   /* Digital Active - tcpwm[0].line[18]:1 */
P0_0_SCB0_UART_RX         = 17,   /* Digital Active - scb[0].uart_rx:0 */
P0_0_SCB7_I2C_SDA         = 18,   /* Digital Active - scb[7].i2c_sda:2 */
```

**读法**：
- 右侧注释告诉你这路信号来自哪个外设实例（`scb[0]` = SCB0）
- `Digital Active` = 工作模式下可用；`Digital Deep Sleep` = 深睡模式仍可用（做 UART 时这条很重要）
- 同一个引脚上出现的不同外设**互斥**，只能选一个

### 2.2 这个封装只有 50 个 GPIO

```
P0.0-0.3    P2.0-2.1    P5.0-5.1    P6.0-6.6    P7.0-7.2    P8.0-8.1
P11.0-11.2  P12.0-12.1  P13.0-13.3  P14.0-14.2  P18.0-18.7
P21.0-21.3  P22.0       P23.3-23.7
```

对智能车来说很紧：4 路电机 PWM + 4 路编码器 = 8 脚，DVP 摄像头还要 10 脚以上。**先画表再动手**。

### 2.3 已核实的两条关键结论

**① P0.0 / P0.1 天生是一对 UART，落在 SCB0：**

```
P0_0_SCB0_UART_RX  = 17
P0_1_SCB0_UART_TX  = 17
```

**② P23.4 / P23.5 / P23.6 是 SWD 调试口，绝对不能配成 GPIO：**

```
P23_4_CPUSS_SWJ_SWO_TDO     = 29
P23_5_CPUSS_SWJ_SWCLK_TCLK  = 29
P23_6_CPUSS_SWJ_SWDIO_TMS   = 29
```

⚠️ **当前 `design.modus` 恰好把这三个脚配成了 GPIO**（strong-out / pull-down / pull-up）。
`cybsp_init()` 一执行就会把 HSIOM 切成 GPIO → 固件跑起来后 CMSIS-DAP / J-Link 立刻连不上，
只能靠"复位瞬间抢连"或擦全片救回来。**第一件事就是删掉这三个 pin。**

### 2.4 引脚规划表（填完再开 DC）

| 功能 | 引脚 | 外设实例 | HSIOM 功能 | 方向 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 调试串口 TX | P0.1 | SCB0 | `SCB0_UART_TX` | 输出 | 115200 8N1 |
| 调试串口 RX | P0.0 | SCB0 | `SCB0_UART_RX` | 输入 | |
| 心跳 LED | (待定) | — | `GPIO` | 输出 | Strong |

| … | | | | | |

## 4. 引脚配置

**两种入口，效果一样：**

- 在 **Pins** 视图点某个引脚 → 下拉选功能（如 `SCB0_UART_TX`）
- 在 **Peripherals** 里配好外设后，DC 会要求你给它分配引脚

只要一个引脚是**纯 GPIO**（LED、按键、方向控制），在 Pins 里选 `GPIO`，然后在 Parameters 里设字段：

| 字段 | 常用值 | 含义 |
| --- | --- | --- |
| `DriveModes` (Drive Mode) | `CY_GPIO_DM_STRONG_IN_OFF` | 推挽输出（驱动 LED / 电机方向） |
| | `CY_GPIO_DM_PULLUP` / `PULLDOWN` | 输入带上/下拉（按键） |
| | `CY_GPIO_DM_HIGHZ` | 高阻输入 |
| `initialState` | `0` / `1` | 上电初始电平 |
| `driveStrength` | `CY_GPIO_DRIVE_1_2` | 驱动强度，默认 1/2 |
| `vtrip` | `CY_GPIO_VTRIP_CMOS` | 输入阈值，CMOS 为标准 |
| `slewRate` | `CY_GPIO_SLEW_FAST` / `SLOW` | 边沿速度，EMI 敏感时用 SLOW |
| `inFlash` | `true` | 初始化代码放 ROM，节省 RAM |
| `isrTrigger` | `CY_GPIO_INTR_DISABLE` | 中断触发方式，做外部中断时选 |
| `nonSec` | `1` | 非安全访问允许 |

保存后每个引脚生成一组宏，形如：

```c
#define ioss_0_port_23_pin_4_ENABLED        1U
#define ioss_0_port_23_pin_4_PORT           GPIO_PRT23
#define ioss_0_port_23_pin_4_PIN            4U
#define ioss_0_port_23_pin_4_DRIVEMODE      CY_GPIO_DM_STRONG_IN_OFF
#define ioss_0_port_23_pin_4_HSIOM          HSIOM_SEL_GPIO
extern const cy_stc_gpio_pin_config_t   ioss_0_port_23_pin_4_config;
```

代码里写 `Cy_GPIO_Write(ioss_0_port_23_pin_4_PORT, ioss_0_port_23_pin_4_PIN, 1)` 即可，**不要硬编码端口号**。

## 5. 外设配置（以 SCB UART 为例）

### 5.1 操作顺序

1. 左侧 **Peripherals** → 展开 **Serial Communication Block (SCB)**
2. 选一个还带 `+` 的空实例（这里是 **SCB0**）→ 点 `+`
3. Personality 选 **UART 3.0**
4. **给别名（Alias）起名**，例如 `DEBUG_UART`
   - 别名决定生成的所有宏名：`DEBUG_UART_HW`、`DEBUG_UART_IRQ`、`DEBUG_UART_config`
   - 一定用大写+下划线，别用中文/空格
5. 右侧 Parameters 按下表填
6. 点 Pins 视图里 P0.0 / P0.1 → 选 `SCB0_UART_RX` / `SCB0_UART_TX`

### 5.2 UART 参数字段（来自 `uart-3.0.cypersonality` 的 `<Member>` 清单）

| 字段 | 设定值 | 说明 |
| --- | --- | --- |
| `ComMode` (UART mode) | `Standard` | 标准 UART，不是 SmartCard/IrDA |
| `Oversample` | `8` | 过采样率，8 是高速常用值 |
| `DataWidth` | `8` | 数据位 |
| `ParityType` | `None` | 校验位 |
| `StopBits` | `1` | 停止位 |
| `BitsOrder` | `LSB First` | 位序 |
| `EnableInputFilter` | `false` | 输入滤波，长线噪声大可开 |
| `FlowControl` | `false` | 硬件流控（CTS/RTS），调试串口不需要 |
| `MultiProc` | `false` | 多机模式 |
| `RxTriggerLevel` / `TxTriggerLevel` | 默认 | FIFO 触发中断的水位 |
| `RxIntrMask` / `TxIntrMask` | `None` | **中断源**，先不勾；要收数据时勾 RX FIFO Not Empty |

> UART 的波特率**不在这个表里** —— 由 DC 自动从外设时钟推算，结果显示在 Parameters 顶部。
> 若误差大到不可接受，回 §6 调时钟分频。

### 5.3 想做 PWM / 定时器的对应外设

| 需求 | Peripherals 树 → Personality |
| --- | --- |
| 电机 PWM | **TCPWM** → `PWM 1.0` / `PWM_v2 1.0` |
| 周期中断（1 kHz 控制环） | **TCPWM** → `Counter_v2 1.0` |
| 编码器正交解码 | **TCPWM** → `Counter_v2 1.0`，Mode 选 Quadrature |
| IMU / 传感器 | **SCB** → `I2C 4.0` |
| 外部 Flash / 摄像头 | **SCB** → `SPI 3.0` |
| 电磁传感器 | **PASS** → SAR ADC |

## 6. 时钟配置

打开 **Clocks** 页。T2G-B-E 的时钟链：

```
IMO (内部主振) → PLL / FLL → PATHMUX → CLKHF (高主频)
                                    → CLK_PERI → [periclk 分频器] → SCB / TCPWM
```

当前工程已配好：`CLKHF0 = 100 MHz`，`PERI divider = 1`。

### ⚠️ 最常踩的坑：分频值是 **1-based**

| 层 | 含义 | 除以 2000 时填什么 |
| --- | --- | --- |
| **DC GUI** | 真实分频比（组数） | **2000** |
| 生成代码 `cycfg_clocks.c` | 寄存器值（-1） | `1999U` |

组件自己会做减一，**你在 GUI 里填的永远是真实分频比**。看到生成代码里是 `1999U` 是对的，不要"修正"它。

### ⚠️ 不要自己算外设频率

时钟链里有 DC 不显示的中间分频（peri group divider、bus divider）。
**一律以 DC Clocks 页显示的频率为准**；你手算 `CLKHF / divider` 得到的值通常是错的（偏高 2~4 倍）。
运行期可用 `Cy_SysClk_ClkPeriGetFrequency()` 复核。

```
bsps/TARGET_CYT2BL3/config/GeneratedSource/
├── cycfg.c / cycfg.h              ← 汇总入口，init_cycfg_all()
├── cycfg_peripherals.c/.h         ← 外设别名 + 配置结构体（新增外设后才出现）
├── cycfg_pins.c/.h                ← 每个引脚的宏与结构体

├── cycfg_clocks.c/.h              ← 分频器
└── cycfg_notices.h                ← ⚠️ 编译期配置错误都在这
```

### 生成后必须做的三项核对

1. **看 `cycfg_notices.h`** —— 有 `#error` 就说明配置有冲突（引脚重复、时钟不够等），先解决
2. **看 `cycfg_peripherals.h`** —— 确认别名宏存在：
   ```c
   #define DEBUG_UART_HW     SCB0
   #define DEBUG_UART_IRQ    scb_0_interrupt_IRQn
   extern const cy_stc_scb_uart_config_t DEBUG_UART_config;
   ```
3. **看 `cycfg_routing.h`** —— 确认引脚真的被路由到外设，而不是 GPIO：
   ```c
   #define ioss_0_port_0_pin_0_HSIOM   P0_0_SCB0_UART_RX
   #define ioss_0_port_0_pin_1_HSIOM   P0_1_SCB0_UART_TX
   ```

> 只看 `cycfg_pins.h` 会误判 —— 它的 `_HSIOM` 宏有 GPIO 兜底默认值，真正生效的是 `cycfg_routing.h`。

## 9. 文件修改：代码骨架

### 9.1 初始化顺序（重要）

`cybsp_init()` 内部**已经**调用了 `cycfg_config_init()` + `cycfg_config_reservations()`
（见 `bsps/TARGET_CYT2BL3/cybsp.c`）→ **不要再调 `init_cycfg_all()`**，会重复初始化。

正确顺序：

```c
int main(void)
{
    cy_rslt_t result = cybsp_init();            /* ① 时钟/电源/引脚/hwmgr */
    if (result != CY_RSLT_SUCCESS) { CY_ASSERT(0); }

    app_uart_init();                            /* ② 外设：PDL Init → Enable */
    app_time_init();                            /* ③ 1 kHz 时基 */
    app_motor_init();                           /* ④ 其他外设 */

    __enable_irq();                             /* ⑤ 最后开全局中断 */

    for (;;) { /* 主循环 */ }
}
```

> 中断注册（`Cy_SysInt_Init` + `NVIC_EnableIRQ`）要在 `__enable_irq()` **之前**做完，
> 否则可能出现"中断来了但向量还没装"。

### 9.2 PDL 外设三段式

DC 只生成**配置结构体**，不生成 Init 调用。每个外设都是 `Init → Enable → (Start)`：

| 外设 | 序列 |
| --- | --- |
| SCB UART | `Cy_SCB_UART_Init(hw, &cfg, &ctx)` → `Cy_SCB_UART_Enable(hw)` |
| SCB I2C | `Cy_SCB_I2C_Init(hw, &cfg, &ctx)` → `Cy_SCB_I2C_Enable(hw)` |
| SCB SPI | `Cy_SCB_SPI_Init(hw, &cfg, &ctx)` → `Cy_SCB_SPI_Enable(hw)` |
| TCPWM PWM | `Cy_TCPWM_PWM_Init(...)` → `Cy_TCPWM_PWM_Enable(...)` → **`Cy_TCPWM_TriggerStart(...)`** |
| TCPWM Counter | `Cy_TCPWM_Counter_Init(...)` → `Cy_TCPWM_Counter_Enable(...)` → **`Cy_TCPWM_TriggerStart(...)`** |

**最容易忘的两条**（"外设像死了一样"的头号原因）：
1. TCPWM 忘了 `TriggerStart` —— Enable 只是放行，不启动计数
2. `cy_stc_scb_uart_context_t` 写在函数里（栈上）—— **必须放文件作用域静态变量**，PDL 内部会一直持有这个指针

写之前先读 PDL 头确认真实签名：

```
mtb_shared/mtb-pdl-cat1/release-v3.25.0/drivers/include/cy_scb_uart.h
mtb_shared/mtb-pdl-cat1/release-v3.25.0/drivers/include/cy_tcpwm_pwm.h
```

### 9.3 也可以走 HAL（`mtb_hal_*`）

本工程 HAL 是 **`mtb_hal_*`**（`mtb-hal-t2gbe4m`），**不是 `cyhal_*`**
（编译宏里没有 `CY_USING_HAL`，`cyhal.h` 那支是死代码）。
HAL 可以帮你管时钟和中断，代价是多一层封装：

```c
/* mtb_hal_uart.h 里实际存在的接口 */
mtb_hal_uart_enable(obj, true);
mtb_hal_uart_set_baud(obj, 115200, &actual);
mtb_hal_uart_write(obj, buf, &len);
mtb_hal_uart_register_callback(obj, cb, args);
```

选型建议：**调试串口 / 简单外设用 HAL 更快；电机 PWM、编码器这种要抠时序的用 PDL 更可控。**

### 9.4 建议的目录结构

按 `mtb-code-style` 规范，`main.c` 控制在 150 行以内，一个功能一个文件：

```
test_cyt2/
├── main.c                  # 只放：init 调用 + 主循环
├── app_config.h            # 引脚别名、缓冲区大小、周期常量
├── app_time.c/h            # 1 kHz 时基 + 毫秒计数
├── app_uart.c/h            # 调试串口 + printf 后端
├── app_motor.c/h           # PWM 占空比映射、限幅、刹车
├── app_encoder.c/h         # 测速、低通滤波
├── app_imu.c/h             # I2C IMU
└── app_ctrl.c/h            # PID 控制环
```

`app_config.h` 里统一收口引脚，杜绝满工程散落 `GPIO_PRT23` 这类硬编码：

```c
/* 引脚别名：改硬件只改这一处 */
#define LED_PORT        ioss_0_port_23_pin_4_PORT
#define LED_PIN         ioss_0_port_23_pin_4_PIN
#define LED_ON()        Cy_GPIO_Clr(LED_PORT, LED_PIN)
#define LED_OFF()       Cy_GPIO_Set(LED_PORT, LED_PIN)
```

## 12. 常见坑速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| GPIO 写不动 | 该脚被外设占用（HSIOM ≠ GPIO） | 查 `cycfg_routing.h`，去 DC 解除外设分配 |
| 外设完全不响应 | PDL 只 Init 没 Enable，或 TCPWM 没 Start | 补 `Enable` / `TriggerStart` |
| 串口输出乱码 | 波特率不匹配；或 context 在栈上 | 核对 baud；context 移文件作用域 |
| 烧完调试器连不上 | SWD 脚被配成 GPIO | 删掉 P23.4/5/6 的 pin 配置 |
| 频率比预期低 2~4 倍 | 手算漏了中间分频 | 以 DC Clocks 页为准 |
| 加了外设但代码里找不到宏 | 保存时没勾"生成代码" | 重开 DC，Ctrl+S 重新生成 |
| 编译报 `cycfg_*.h` 里的错 | 配置冲突 | 看 `cycfg_notices.h`，回 DC 修 |
| 新增 `.c` 没被编译 | 放到了被排除的目录 | 放工程根或任意子目录（自动递归） |
