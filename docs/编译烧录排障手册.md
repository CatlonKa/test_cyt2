## 0. 速查表

> 除第 1、2 条外，其余条目只发生在 **DAPLink / OpenOCD 路线**；J-Link 走 SEGGER loader，不受影响。

| 现象 | 原因 | 解法 |
|---|---|---|
| `kitprog3: get_version command failed` | 用了 `make program`，但探针不是 KitProg3 | 用 `Program` 任务，不要用 `make program` |
| `SROM API execution failed. Status: 0x080010DC` | 未复位就直接擦 flash | 先 `traveo2 reset_halt sysresetreq` 再写 |
| `clearing lockup after double fault` | CM0+ 里的 flash 算法跑飞（上一次失败残留） | `reset run` 清掉，或断电重上电 |
| `Error connecting DP: cannot read IDR` | SYSRESETREQ 后调试域关闭 | **这是正常的**，别当错误 |
| `CM0+ PC = 0x0800_xxxx` 或 `0xFFFFFFFE` | 残留 flash 算法卡在 SRAM / Lockup | §2.4 |
| 库头文件大段显示为灰色 | clangd 找不到 `compile_commands.json` | §5 |
| `Unexpected command line argument: [find` | `Start-Process` 不给含空格参数加引号 | §4.3 |
| DAPLink 烧录要 30 s 以上 | OpenOCD 在复位后死等重连 | §3 |

## 1. 探针与烧录路径

### 1.1 哪些探针能用

| 探针 | 能否烧录 | 说明 |
|---|---|---|
| **J-Link**（`1366:0105`，含仿制品） | ✅ **1.7 s** | SEGGER 自有 T2G loader，不走 SROM API，**最稳最快** |
| **CMSIS-DAP / DAPLink**（`C251:F001`） | ✅ 8~9 s | 走 OpenOCD，必须先复位（§2.1） |
| 逐飞 ZF-WLFS-DAP（`5A46:4101`） | ❌ 不能 | 硬件问题：`SWDIO/TMS=0`，读不到 DPIDR |
| KitProg3 / MiniProg4 | ✅ 能 | `make program` 原生支持；唯一具备 test-mode acquire |

仿制 J-Link（如 `J-Link OB-Mini Plus-CortexM`）**不用接 VTref**，内部自带电平检测（实测读回 3.300V）。

### 1.2 为什么不能用 `make program`

`recipe-make-cat1a/.../program_common.mk:65` 写死
`_MTB_RECIPE__OPENOCD_INTERFACE=source [find interface/kitprog3.cfg]`，只支持 KitProg3 / JLink。
DAPLink 会得到 `Error: kitprog3: get_version command failed`（`make: *** 错误 1`）。

→ **所有烧录走 `scripts/flash.ps1`，不要走 make。**

## 2. 本工程的烧录配方（关键）

### 2.1 DAPLink 三步骤（必须按顺序）

```
① traveo2 reset_halt sysresetreq   ← 复位，让 flash 算法环境干净
② halt + flash write_image erase   ← 擦写
③ reset run                        ← 启动固件
```

不复位直接擦，CM0+ 里的 flash 算法必然 double fault：
`clearing lockup after double fault` → `SROM API execution failed. Status: 0x080010DC`。

①② 不能合并进同一个 OpenOCD 会话：复位会关闭调试域（DP），断开的连接拿不回来。

### 2.2 已排除的因素（别再重复试）

「不复位直接写」必然失败的前提下，**SWD 时钟（50~2000 kHz）、主频（8~160 MHz）、供电、
MPU/中断/双核、擦除方式、flash bank、算法工作区地址、复位方式**全部无关，已逐一试过。

`Status: 0x080010DC` 是**假状态码**：等于 `WORKAREAADDR + 0x8DC`，改工作区地址它跟着变
（`0x08018000` → `0x080188DC`），不要拿去查手册。

`reset_config srst_only` + `reset halt` 同样不行：nRESET 复位也会关闭调试域。

> J-Link 不需要 §2.1 的复位技巧，以上因素一概无关。

### 2.3 J-Link 配方

```
JLink.exe -NoGui 1 -ExitOnError 1 -Device CYT2BL3CAS_M0 -If SWD -Speed 4000 -CommandFile <脚本>
```

脚本内容：`Connect` / `exec EnableEraseAllFlashBanks` / `LoadFile <hex，正斜杠> 0 reset` /
`Reset` / `Go` / `Exit`。

- `_M0` 后缀必须：T2G 只能通过 CM0+ 烧 flash；`_M4` 只能看 CM4。
- **不需要**任何复位技巧，SEGGER loader 自己处理。

### 2.4 恢复卡死状态

`CM0+ PC = 0x0800_xxxx`（残留算法）或 `0xFFFFFFFE`（Lockup）时，用 `reset run` 清掉，不必断电
（完整命令见 §11）；不行再断电重上电。J-Link 的 `LoadFile ... 0 reset` 也能清。

## 3. DAPLink 烧录速度（31.3 s → 8.3 s）

只对 DAPLink 有意义；**J-Link 1.7 s，不用看这一节**。

| 步骤 | 前 | 后 | 做法 |
|---|---|---|---|
| `Find-JLinkExe` 递归搜索 | 2.15 s | 0.013 s | 已知路径用 `Test-Path` |
| 探针检测 | 1.78 s | 1.04 s | `Get-CimInstance` 过滤 `USB\VID_1366%` |
| **reset 步骤** | **23.8 s** | **2.4 s** | 轮询输出，见下 |
| write + verify | 1.9 s | 1.9 s | 必须自然跑完 |
| reset run（启动） | 3.5 s | 3.5 s | **不能 kill** |

**23.8 s 的来源**：`reset_halt sysresetreq` 后调试域立刻关闭，OpenOCD 不知情，重试 **44 次**
`cannot read IDR` 才放弃；复位本身是瞬时的 → **见到第一行 `cannot read IDR` 就 kill 进程**。

**只有第 ① 步能 kill**；write/verify/reset run 必须自然跑完，kill 会让 CM0+ 卡在 SRAM。

## 4. OpenOCD 使用陷阱

### 4.1 必须用 Infineon 版 OpenOCD

只有 `D:\Infineon\Tools\ModusToolboxProgtools-2.0\openocd` 带 `traveo21` flash 驱动；本机另外 4 个
（sysprogs / xpack / TI / EIDE，均 0.12.0）都没有，且缺 `-power-down-on-quit` → **换不了**。

检查：二进制里搜 `traveo21` 字符串（`[Text.Encoding]::ASCII.GetString(...)`）。

### 4.2 用不了的两条路

- OpenOCD 的 `interface/jlink.cfg`：报 `LIBUSB_ERROR_NOT_FOUND`（SEGGER 驱动占着设备）。
  Zadig 换 WinUSB 能用，但**会破坏 `JLink.exe`**，不划算。
- KitProg3 的 test mode acquire：`mxs40_acquire` 内部就是 `kitprog3 acquire_psoc`
  （`func_mxs40.tcl:513`），通用探针无等价命令。日志 `** Test Mode acquire not supported`
  就是缺它，非致命，可忽略。

### 4.3 `Start-Process` 不自动加引号（隐蔽坑）

```powershell
# ❌ 'source [find ...]' 被拆开 → Unexpected command line argument: [find
# ✅ 含空格的参数自己加引号
function Quote-Args([string[]]$a) {
    ($a | ForEach-Object { if ($_ -match '\s') { '"' + $_ + '"' } else { $_ } })
}
```

### 4.4 `traveo2` 命令组

| 命令 | 说明 |
|---|---|
| `traveo2 reset_halt [sysresetreq\|vectreset]` | 复位并 halt（会丢 DP） |
| `traveo2 mass_erase <bank>` | 整片擦除 |
| `traveo2 sflash_restrictions <0-3>` | SFlash 写保护 |
| `set_region_size` / `wflash blank_map` | 少见 |

`traveo2` **没有** `sromcall`（那是 `macaw` 系列的）。

## 5. 编辑器 / IntelliSense

`cy_gpio.h` 第 259 行起整块灰化，但**实际是编译的**（`cyt2bl3cas.h:595` 定义了 `CY_IP_MXS40IOSS`）。

根因：`C_Cpp.intelliSenseEngine: disabled`，判灰的是 **clangd**；`mtb_shared` 是独立 workspace 根，
往上找不到 `compile_commands.json`（只在 `test_cyt2/build/` 有）。

解法：新建 `d:\Infineon\mtw\mtb_shared\.clangd`，再 `clangd: Restart language server`：

```yaml
CompileFlags:
  CompilationDatabase: ../test_cyt2/build
```

验证：`clangd.exe --check="<文件>"` 应含 `Loaded compilation database` + `-DCYT2BL3CAS`。
⚠️ 末尾 "All checks completed, N errors" 是 clangd **内部 tweak 自测**计数，不是源码错误。

**不要开 cpptools**：会与 clangd 同时解析、互相干扰。

## 6. 编译系统注意事项

| 事项 | 说明 |
|---|---|
| 源码自动发现 | 从工程根**递归**收集 `*.c/*.cpp/*.s`，`SOURCES`/`INCLUDES` 留空即可 |
| `Copy-Item` 还原文件 | **保留原时间戳** → ninja 不重编。需 `(Get-Item x.c).LastWriteTime = Get-Date` 或 `make clean` |

| `device-configurator-cli` | 只能 `--build/--set-device/--update`，加外设必须用 GUI（`make config`） |

## 7. VS Code 任务配置

### 7.1 当前任务一览

| 任务 | 行为 | 耗时（DAPLink） |
|---|---|---|
| **`Build`**（默认，`Ctrl+Shift+B`） | **只编译**（增量） | ~1.5 s |
| **`Program`** | **只烧录**（读 `cyt2.defaultProbe`） | ~9 s |
| `Program (DAPLink, fast)` | 只烧录，跳过探针检测 | ~8 s |
| **`Build & Program`** | **只烧录**（§7.2，被插件 Program 按钮绑定） | ~9 s |
| **`Erase Device`** | **擦主 flash**（Erase 按钮默认模式） | ~8 s |
| **`Erase All`** | **擦主 + work flash**（Erase 的另一种模式） | ~16 s |
| **`Quick Program`** | 只烧录 + 跳过校验（Program 的另一种模式） | ~8 s |
| `Rebuild` | Clean + Build | ~5 s |
| `Advanced Programming` | ⚠️ `make advanced_program`（KitProg3），通用探针会失败 | — |
| `Tool: Library Manager` | `make modlibs` | — |

> 上表是 DAPLink 数据。**J-Link 快很多**（仅烧录 ~2 s），`Erase` 同理。
> 当前 `settings.json` 为 `jlink`。
>
> **没有「一键编译+烧录」任务**：快捷键只能绑单个任务，要编译+烧录就 `Ctrl+Shift+B` 再 `Program`。
> `Ctrl+Shift+B` 跑的是 tasks.json 里**唯一** `isDefault: true` 的任务（现为 `Build`），
> 不是“重复上一次”；想改成只烧录就把它移到 `Program`。

### 7.2 ⚠️ 插件按钮 → 任务名（写死在扩展里）

主页 5 个按钮 `Build` `Rebuild` `Clean` `Erase` `Program`。扩展不注册命令，而是
`mapActionToTask()`（`dist/extension.js`）按**任务名精确匹配**再 `executeTask()`：

```js
"build":"Build"   "rebuild":"Rebuild"   "clean":"Clean"   "program":"Build & Program"
"quick-program":"Quick Program"   "erase":"Erase Device"   "erase-all":"Erase All"
```

`Program` / `Erase` 是**带模式切换**的按钮（右键切换）：

| 按钮 | 默认 | 右键 | 本工程与之的差异 |
|---|---|---|---|
| Program | `Build & Program` | `Quick Program` | **只烧录**（原厂编译+烧录）；Quick 额外**不校验** |
| Erase | `Erase Device` | `Erase All` | **只擦 main**（原厂含 super flash/eFuse，擦了可能锁死）；All = main + work |

**关键手法**：改按钮行为 = 改**同名任务的内容**，**任务名不能改**（一改就弹
`The requested task '...' does not exist`）。要编译+烧录就 `Build` 后手动 `Program`。

擦除用 `traveo2 mass_erase 0`(main) / `1`(work)，不用 recipe 的 `erase_all`（会连 SFlash 一起擦）。
⚠️ work flash 擦后 `mdw` 读回随机值 → **SWD 直读 work flash 不可验证**；main flash 可以。

### 7.3 日常用法

| 场景 | 操作 |
|---|---|
| 改了代码 | `Build` → `Program`（先看 Problems 面板） |
| 只重启板子 | `Program` |
| 怀疑 flash 脏 / 校验失败 | `Erase` → `Program` |
| 彻底清空 | 右键 `Erase` → `Erase All` |
| 最快（不管校验） | 右键 `Program` → `Quick Program` |
| 改了 `design.modus` / `Makefile` | `Rebuild` → `Program` |

`Program` **不编译**，改了代码直接点会烧旧 hex（有 stale-hex 黄色警告但不阻止）。
`Ctrl+Shift+B` = `Build`（只编译）。

**Erase 何时用**：`verify` 失败或报 `SROM API execution failed` 时先擦再烧。平时不必 ——
`flash write_image erase` 已自动擦掉目标扇区，额外 `Erase` 只是把空闲区也填 `0xFFFFFFFF`。
本板无外部 QSPI，一般点 `Erase` 就够。

**不要用**：`Advanced Programming`（要 KitProg3）、"Fix Tasks and Settings"（§7.4）、
`make program` / `make erase`（§1.2）。

### 7.4 ⚠️ "Fix Tasks and Settings" 会破坏配置

点 `modusToolbox.fixTasksAndSettings` 会：① 把 `Build & Program` 改回 `make program`（必失败）；
② 给多个任务加 `isDefault: true`（与 `Build` 冲突）；③ 删掉手写注释。诊断：`git diff .vscode/tasks.json`。
该 fix 对标准 KitProg3 板是对的，本工程不适用。
`.vscode/c_cpp_properties.json` 被自动更新（同步 include 路径）**是修复，应保留**。

### 7.5 图标栏 / Quick Tasks 无法自定义

右上角图标栏只有扩展贡献的 `modusToolbox.mtbMainPage`；主页 Quick Tasks 由 `sendTasks()` 硬编码
（`Add AI Enhancements` 显示灰色 = `.github/` 已存在）。**两者 `tasks.json` 都改不了**，
想加快捷入口只能 `Tasks: Run Task` 或绑快捷键（§8.2）。

## 8. flash.ps1

```powershell
.\scripts\flash.ps1                  # 用 settings.json 的 cyt2.defaultProbe
.\scripts\flash.ps1 -Probe daplink   # 强制 DAPLink（覆盖设置）
.\scripts\flash.ps1 -SkipVerify      # 不做回读校验
.\scripts\flash.ps1 -Erase Main      # 只擦主 flash
.\scripts\flash.ps1 -Erase All       # 擦 main + work flash
```

### 8.1 探针选择

配置位置：`.vscode/settings.json` 的 `cyt2.defaultProbe`。

| 值 | 含义 | 耗时 |
|---|---|---|
| `jlink` | SEGGER J-Link，不检测 | **~2 s** |
| `daplink` | CMSIS-DAP / DAPLink，不检测 | ~8 s |
| `auto` | 每次检测（PnP 枚举 ~1.1 s） | 命中分支耗时 +1.1 s |

优先级：**命令行 `-Probe` > `settings.json` > `auto`**。`auto` 会打印
`Probe: auto-detect took N.N s`。填错探针（插 J-Link 却写 `daplink`）会失败。

当前 `settings.json` 为 `"cyt2.defaultProbe": "jlink"`。

### 8.2 切换探针

改 `settings.json` 的值即可；单次覆盖用 `-Probe`。预置任务：`Program`（读配置）、
`Program (DAPLink, fast)`（强制 daplink）。

绑快捷键：`Ctrl+K Ctrl+S` → `workbench.action.tasks.runTask` → `args: "Program"`。
⚠️ `keybindings.json` **只能是用户级**（`%APPDATA%\Code\User\keybindings.json`）。
快捷键只能绑单个任务，`Program` 不编译 —— 改了代码先 `Ctrl+Shift+B`。

### 8.3 成功判据与内置保护

| 保护 | 说明 |
|---|---|
| stale-hex 警告 | 源文件比 hex 新时提示先 Build（不阻止烧录） |
| 残留算法检测 | 报错时提示断电重上电 |
| 耗时打印 | 末行 `FLASH OK (xxx) in N.N s.` |

**成功判据**（两种探针输出不同）：

- **J-Link**：`Erasing/Programming/Verifying flash [100%] Done` → `O.K.`，
  以及 `Bank 0 @ 0x10000000: 2 ranges affected (65536 bytes)`。
- **DAPLink**：`wrote NNNNN bytes` + `verified NNNNN bytes`。
  `wrote 12800` 与 `verified 12116` 不一致是正常的（写入按扇区对齐、校验按实际长度）；
  `verified` 应等于 Build 报的 `Total FLASH (Utilized)`。

### 8.4 ⚠️ 编码坑：中文 + PowerShell 5.1

PS 5.1 按 ANSI（GBK）解读，**不假设 UTF-8** → `Get-Content`/`Set-Content` 处理中文会双重编码并固化；
含中文且**无 BOM** 的 `.ps1` 直接**语法报错**（本工程用 `powershell.exe` 5.1）。

| 文件类型 | 规则 |
|---|---|
| 数据文件（`settings.json`） | `[IO.File]::ReadAllText/WriteAllText` + 显式 UTF-8，存**无 BOM** |
| 含中文的 `.ps1` | **必须 UTF-8 带 BOM**（PS 5.1 识别 UTF-8 脚本的唯一途径） |
| 纯 ASCII `.ps1` | 无需 BOM |

```powershell
$t = [IO.File]::ReadAllText($f, [Text.Encoding]::UTF8)                        # 读（自动剥 BOM）
[IO.File]::WriteAllText($f, $t, (New-Object System.Text.UTF8Encoding $false))  # 无 BOM
[IO.File]::WriteAllText($f, $t, (New-Object System.Text.UTF8Encoding $true))   # 带 BOM
```

## 10. 关键地址与数值

| 项 | 地址 / 值 |
|---|---|
| 主 flash | `0x10000000`（4 MB，实际 4160 KB） |
| work flash | `0x14000000`（128 KB） |
| SRAM | `0x08000000` |
| `WORKAREAADDR`（flash 算法 RAM） | `0x08000800`，32 KB |
| `CPUSS.CM0_CTL` | `0x40201000` |
| `CPUSS.CM0_CLOCK_CTL` | `0x40201008` |
| `CLK_ROOT_SELECT[0]` | `0x40261240` |
| `MPU_CTRL` | `0xE000ED94` |
| `SystemCoreClock` | 变量，看 `.map` 或 `nm`（约 `0x0802069C`） |
| CM0+ 正常运行 PC | `0x10000A06`（`__cy_m0p_code_start`，CM0P_SLEEP） |
| 正常 `SWD DPIDR` | `0x6BA02477` |

**永远不要手算外设频率** —— 用 Device Configurator 的 Clocks 页，
或读 `Cy_SysClk_ClkPeriGetFrequency()`。
