## 0. 速查表

| 现象 | 原因 | 解法 |
|---|---|---|
| `kitprog3: get_version command failed` | 用了 `make program`，但探针不是 KitProg3 | 用 `Program` 任务，不要用 `make program` |
| `SROM API execution failed. Status: 0x080010DC` | 未复位就直接擦 flash | 先 `traveo2 reset_halt sysresetreq` 再写 |
| `clearing lockup after double fault` | CM0+ 里的 flash 算法跑飞（上一次失败残留） | `reset run` 清掉，或断电重上电 |
| `Error connecting DP: cannot read IDR` | SYSRESETREQ 后调试域关闭 | **这是正常的**，别当错误 |
| `CM0+ PC = 0x0800_xxxx` | 残留的 flash 算法卡在 SRAM | `reset run` 或断电重上电 |
| `CM0+ PC = 0xFFFFFFFE` | Lockup | `reset run` 或断电重上电 |
| 库头文件大段显示为灰色 | clangd 找不到 `compile_commands.json` | 见 §5 |
| `Unexpected command line argument: [find` | `Start-Process` 不自动给含空格参数加引号 | 见 §4.3 |
| 烧录要 30 秒以上 | OpenOCD 在复位后死等重连 | 见 §4.2 |

## 1. 探针与烧录路径

### 1.1 哪些探针能用

| 探针 | 能否烧录 | 说明 |
|---|---|---|
| **CMSIS-DAP / DAPLink**（`C251:F001`） | ✅ 能，8~9 s | 走 OpenOCD，需先复位（§3） |
| **J-Link**（`1366:0105`，含仿制品） | ✅ 能，约 3 s | SEGGER 自有 T2G loader，不走 SROM API |
| 逐飞 ZF-WLFS-DAP（`5A46:4101`） | ❌ 不能 | 硬件问题：`SWDIO=0`，读不到 DPIDR |
| KitProg3 / MiniProg4 | ✅ 能 | 唯一支持 `make program` 和 test-mode acquire 的探针 |

**仿制 J-Link 说明**：即使没有 VTref 引脚也能用。实测 `J-Link OB-Mini Plus-CortexM`
读回 `VTref = 3.300V`，内部自带电平检测。

### 1.2 为什么不能用 `make program`

`mtb_shared/recipe-make-cat1a/release-v2.8.0/make/recipe/program_common.mk:65` 写死了：

```make
_MTB_RECIPE__OPENOCD_INTERFACE=source [find interface/kitprog3.cfg];
```

只有 KitProg3 / JLink 被支持。用 DAPLink 会得到：

```
Error: kitprog3: get_version command failed
** OpenOCD init failed **
make: *** [program_common.mk:144：program_KitProg3] 错误 1
```

→ **所有烧录走 `scripts/flash.ps1`，不要走 make。**

## 2. 本工程的烧录配方（关键）

### 2.1 DAPLink 三步骤（必须按顺序）

```
① traveo2 reset_halt sysresetreq   ← 复位，让 flash 算法环境干净
② halt + flash write_image erase   ← 擦写
③ reset run                        ← 启动固件
```

**为什么必须 ①**：不复位直接擦，算法在 CM0+ 里必然 double fault：

```
clearing lockup after double fault
error waiting for target flash write algorithm
SROM API execution failed. Status: 0x080010DC
failed erasing sectors 0 to 0
```

**为什么 ①② 不能合进同一个 OpenOCD 会话**：复位会关闭调试域（DP），
同一会话拿不到已断开的连接。必须分成两次调用。

### 2.2 已排除的因素（别再重复试）

在「不复位直接写」必然失败的前提下，以下**全部无关**：

| 因素 | 试过的值 | 结论 |
|---|---|---|
| SWD 时钟 | 50 / 100 / 500 / 1000 / 2000 kHz | 无关 |
| 主频 | 160 / 100 / 80 / 40 / 8 MHz | 无关 |
| 供电 | 换过电源 | 无关 |
| MPU / SMPU / PPU | `MPU_CTRL` 本来就是 0；生成代码无保护配置 | 无关 |
| 中断 | 双核 NVIC 全禁 + 清 pending | 无关 |
| 双核冲突 | 先 halt CM4 再 halt CM0+ | 无关 |
| 擦除方式 | `flash erase_sector` / `traveo2 mass_erase 0` | 同样失败 |
| flash bank | 主 flash / work flash | 同样失败（全局问题） |
| 算法工作区地址 | `0x08000800` / `0x08018000` | 无关 |
| 复位方式 | `reset` / `reset halt` / `vectreset` / `srst_only` | 见下 |

**`Status: 0x080010DC` 是假的状态码**：它等于 `WORKAREAADDR + 0x8DC`，
把工作区改到 `0x08018000` 后该值跟着变成 `0x080188DC`。
→ 不要把这个数当 SROM 错误码去查手册。

**`reset_config srst_only` + `reset halt` 也不行**（nRESET 已接）：
报 `AP write error, reset will not halt` 和 `Vector Table not found`。
nRESET 复位同样会关闭调试域。

### 2.3 J-Link 配方

```
JLink.exe -NoGui 1 -ExitOnError 1 -Device CYT2BL3CAS_M0 -If SWD -Speed 4000 -CommandFile <脚本>
```
脚本内容：
```
Connect
exec EnableEraseAllFlashBanks
LoadFile <hex，正斜杠> 0 reset
Reset
Go
Exit
```

- `_M0` 后缀必须：T2G 只能通过 CM0+ 烧 flash。`_M4` 只能看 CM4 的状态。
- 不需要接 VTref（仿制品内部自带）。
- **不需要**任何复位技巧，SEGGER loader 自己处理。

### 2.4 恢复卡死状态

芯片卡住时（`CM0+ PC = 0x0800_xxxx` 或 `0xFFFFFFFE`）：

```powershell
# 不用断电，一条命令搞定
openocd -s <scripts> -c "source [find interface/cmsis-dap.cfg]" `
        -c "transport select swd" -c "source [find target/traveo2_be_4m.cfg]" `
        -c "adapter speed 1000" -c "init" -c "reset run" -c "shutdown"
```

不行就断电重上电。

## 3. 烧录速度优化（31.3 s → 8.3 s）

### 3.1 各步骤实测耗时

| 步骤 | 优化前 | 优化后 | 做法 |
|---|---|---|---|
| `Find-JLinkExe` 递归搜索 | 2.15 s | 0.013 s | 已知路径用 `Test-Path`（快 165 倍） |
| 探针检测 | 1.78 s | 1.04 s | `Get-CimInstance -Filter "DeviceID LIKE 'USB\VID_1366%'"` |
| **reset 步骤** | **23.8 s** | **2.4 s** | 轮询输出，见 §3.2 |
| write + verify | 1.9 s | 1.9 s | 必须自然跑完 |
| reset run（启动） | 3.5 s | 3.5 s | **不能 kill** |
| `-Probe daplink` | — | 跳过检测 | 直接指定探针 |

其他参考数据：
- OpenOCD 单次启动约 **0.1 s**（不是瓶颈）
- `make build` 无改动约 **1.5 s**（不是瓶颈）

### 3.2 那 23.8 秒是怎么来的

`traveo2 reset_halt sysresetreq` 发出复位后，调试域立刻关闭，
但 OpenOCD **不知道**，反复重试 **44 次** `cannot read IDR` 才放弃。

```
Error: Error connecting DP: cannot read IDR    ← ×44
Polling target traveo2_be_4m.cpu.cm0 failed, trying to reexamine
Error: [traveo2_be_4m.cpu.cm0] Examination failed
```

**复位本身是瞬时的**。所以：轮询输出，看到第一行 `cannot read IDR` 就 Kill 掉进程。

### 3.3 试过但不可行的优化

| 方案 | 结果 |
|---|---|
| `reset run` 代替 `reset_halt sysresetreq` | ❌ 算法必崩（应用在跑，SROM 环境被破坏） |
| write/verify/reset run 合并同一会话 | ❌ 只省 0.3 s，且 reset run 会拖 23 s |
| 固定等 1.2 s 后 kill（不轮询） | ❌ 太早，复位未执行，写入必失败 |
| 轮询 write/verify 输出后 kill | ❌ 输出有缓冲，会误判"已写完" |
| kill `reset run` 那一步 | ❌ CM0+ 卡在 SRAM（`0x0800_xxxx`） |

**结论：只有第 ① 步能 kill，且必须靠 `cannot read IDR` 判断时机。**

### 3.4 最短安全等待时间实测

kill 前固定等待的测试结果（都能 PASS，但只说明复位已生效，不如轮询精确）：

| 等待 | 结果 |
|---|---|
| 700 ms | PASS |
| 900 ms | PASS |
| 1100 ms | PASS |
| 1300 ms | PASS |

脚本最终采用**轮询 `cannot read IDR`**（约 2.4 s），比固定等待更可靠。

## 4. OpenOCD 使用陷阱

### 4.1 必须用 Infineon 版 OpenOCD

本机 5 个 OpenOCD，**只有 Infineon 那个有 `traveo21` flash 驱动**：

| 路径 | `traveo21` 驱动 |
|---|---|
| `D:\Infineon\Tools\ModusToolboxProgtools-2.0\openocd` | ✅ 有 |
| `D:\OpenOCD\bin\openocd.exe`（sysprogs 0.12.0） | ❌ 无 |
| `D:\stm32_tools\xpack-openocd-0.12.0-7` | ❌ 无 |
| `D:\TI\openocd-20250710\...` | ❌ 无 |
| `C:\Users\<user>\.eide\tools\openocd_*\...` | ❌ 无 |

上游 OpenOCD 还会因缺少 Infineon 私有参数 `-power-down-on-quit` 直接报错：

```
Error: Unknown param: -power-down-on-quit
```

**检查方法**（在二进制里搜字符串）：
```powershell
$t = [Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes($exe))
$t -match 'traveo21'
```

### 4.2 OpenOCD 的 J-Link 接口用不了

`interface/jlink.cfg`（`adapter driver jlink`）会报：
```
Failed to open device: LIBUSB_ERROR_NOT_FOUND
Error: No J-Link device found
```
SEGGER 专有驱动占着设备，libusb 拿不到。
用 Zadig 换 WinUSB 能让 OpenOCD 用上 J-Link，但**会破坏 `JLink.exe` 本身**，不划算。

### 4.3 `Start-Process` 不自动加引号（隐蔽坑）

```powershell
# ❌ 错：'source [find interface/cmsis-dap.cfg]' 被拆成 3 个参数
Start-Process $ocd -ArgumentList @('-c','source [find interface/cmsis-dap.cfg]')
# → OpenOCD 报: Unexpected command line argument: [find
# → 复位根本没执行，后续写入必然失败

# ✅ 对：手动加引号
function Quote-Args([string[]]$a) {
    return ($a | ForEach-Object { if ($_ -match '\s') { '"' + $_ + '"' } else { $_ } })
}
```

### 4.4 `traveo2` 命令组

| 命令 | 说明 |
|---|---|
| `traveo2 reset_halt [sysresetreq\|vectreset]` | 复位并 halt（会丢 DP） |
| `traveo2 mass_erase <bank>` | 整片擦除 |
| `traveo2 sflash_restrictions <0-3>` | SFlash 写保护 |
| `set_region_size` / `wflash blank_map` | 少见 |

`traveo2` **没有** `sromcall`（那是 `macaw` 系列的）。

### 4.5 KitProg3 专有能力

`func_mxs40.tcl:513` 里 `mxs40_acquire` 内部就是 `kitprog3 acquire_psoc` —— 
**通用探针没有等价命令**。日志里那句
`** Test Mode acquire not supported by selected adapter` 就是缺这个能力，
非致命，可以忽略。

## 5. 编辑器 / IntelliSense

### 5.1 库头文件大段灰色 = 显示问题，不是编译问题

打开 `mtb_shared/.../drivers/include/cy_gpio.h`，第 259 行起整块（到 2891 行）灰化：

```c
#if defined (CY_IP_MXS40SIOSS) || defined (CY_IP_MXS40IOSS) || defined (CY_IP_MXS22IOSS)
```

**实际是编译的** —— 宏链：
```
cy_gpio.h:257  #include "cy_device.h"
  → cy_device_headers.h:440  #elif defined (CYT2BL3CAS)
    → #include "cyt2bl3cas.h"
      → cyt2bl3cas.h:595  #define CY_IP_MXS40IOSS 1u   ✅
```

**根因**：`.vscode/settings.json` 里 `"C_Cpp.intelliSenseEngine": "disabled"`，
实际是 **clangd** 在判断。`mtb_shared` 是独立 workspace 根，
往上找不到 `compile_commands.json`（只在 `test_cyt2/build/` 有）。

**解法**：新建 `d:\Infineon\mtw\mtb_shared\.clangd`：
```yaml
CompileFlags:
  CompilationDatabase: ../test_cyt2/build
```
然后 `Ctrl+Shift+P → clangd: Restart language server`。

**验证方法**：
```powershell
& "$env:APPDATA\Code\User\globalStorage\llvm-vs-code-extensions.vscode-clangd\install\*\clangd_*\bin\clangd.exe" --check="<文件路径>"
# 应输出: Loaded compilation database from ... / Compile command inferred from ... -DCYT2BL3CAS
```
⚠️ `--check` 末尾的 "All checks completed, N errors" 是 clangd **内部 tweak 自测**
（`DefineOutline ==> FAIL`）计数，**不是源码错误**。

### 5.2 不要打开 cpptools

`C_Cpp.intelliSenseEngine` 保持 `disabled`。开启后 cpptools 与 clangd 会同时解析、互相干扰。

## 6. 构建系统注意事项

| 事项 | 说明 |
|---|---|
| 源码自动发现 | 从工程根**递归**收集 `*.c/*.cpp/*.s`，`SOURCES`/`INCLUDES` 留空即可 |
| `Copy-Item` 还原文件 | **保留原时间戳** → ninja 不重编。需 `(Get-Item x.c).LastWriteTime = Get-Date` 或 `make clean` |
| `cybsp_init()` | 已含 `cycfg_config_init()` + `cycfg_config_reservations()`，**不要再调 `init_cycfg_all()`** |

| `device-configurator-cli` | 只能 `--build/--set-device/--update`，加外设必须用 GUI（`make config`） |

## 7. VS Code 任务配置

### 7.1 当前任务一览

| 任务 | 行为 | 耗时 |
|---|---|---|
| **`Program`**（默认，`Ctrl+Shift+B`） | **只烧录，不编译** | ~9 s |
| `Program (DAPLink, fast)` | 只烧录，跳过探针检测 | ~8 s |
| `Build` | 只编译 | ~1.5 s |
| `Build & Program` | 编译 + 烧录 | ~10.5 s |
| `Build & Program (DAPLink, fast)` | 编译 + 烧录，跳过检测 | ~9.5 s |
| `Rebuild` | Clean + Build | ~5 s |
| `Erase Device` / `Erase All` | ⚠️ 走 `make erase`（KitProg3），DAPLink 下会失败 |
| `Advanced Programming` / `Quick Program` | ⚠️ 同上 |

**`Program` 是默认构建任务**：工具栏按钮 / `Ctrl+Shift+B` 直接烧现有 hex。
想让 `Ctrl+Shift+B` 只编译，把 `"isDefault": true` 从 `Program` 移到 `Build`。

### 7.2 ⚠️ Infineon 插件的 "fix task" 会破坏配置

点一次 "fix task"（ModusToolbox 扩展提供）会：

1. 把 `Build & Program` **改回 `make program`** → DAPLink 下必失败
2. 给 `Rebuild` / `Build & Program` 重新加 `isDefault: true` → 与 `Build` 冲突
3. 删掉手写注释

**诊断**：
```powershell
git diff .vscode/tasks.json
```

**正确状态**：
- `isDefault` **只能有一个**（当前是 `Program`）
- `Build & Program` 必须是 `dependsOn: ["Build", "Program"]`
- `Build & Program` 绝不能是 `make program`

**该 fix 对标准 KitProg3 开发板是对的，对本工程（自制板 + DAPLink）是错的。**
如果将来换了 KitProg3，可以重新跑这个 fix。

## 8. flash.ps1 使用说明

```powershell
.\scripts\flash.ps1                 # 自动检测探针
.\scripts\flash.ps1 -Probe daplink   # 跳过检测（最快）
.\scripts\flash.ps1 -Probe jlink     # 强制 J-Link
.\scripts\flash.ps1 -SkipVerify      # 不做回读校验
```

内置保护：

| 保护 | 说明 |
|---|---|
| stale-hex 警告 | 源文件比 hex 新时提示"先 Build"（不会阻止烧录） |
| 残留算法检测 | 报错时提示断电重上电 |
| 耗时打印 | 最后一行显示 `FLASH OK (xxx) in N.N s.` |

正常输出样例：
```
HEX : ...\build\last_config\mtb-example-empty-app.hex
Probe: CMSIS-DAP (daplink mode)
   wrote 12800 bytes ... (8.4 KiB/s)
   verified 12204 bytes ... (70.0 KiB/s)

FLASH OK (CMSIS-DAP) in 8.2 s.
```

**`wrote 12800` 与 `verified 12204` 不一致是正常的**：
写入按扇区边界对齐（12 KB），校验按实际数据长度。
`verified` 的字节数应等于 Build 报的 `Total FLASH (Utilized)`。

## 9. 调试（Attach）现状

**F5 调试目前不可用**，原因有两层：

1. `openocd.tcl` 写死 `source [find interface/kitprog3.cfg]`
2. 更根本：调试需要复位进 `reset halt`，而复位必然关闭调试域（§2.1）

`launch.json` 的启动序列里有 `monitor traveo2 reset_halt sysresetreq`，
Cortex-Debug 在同一个 gdb server 会话里做不到"复位后重连"。

**理论上可行的折中**：纯 `attach`（不负位、不烧录），
实测 `halt` + 读寄存器 + 读内存都正常，可以打断点单步。
但 `restart` / `reset halt` 会断。需要时再配置。

## 10. 关键地址与数值

| 项 | 地址 / 值 |
|---|---|
| 主 flash | `0x10000000`（4 MB，实际 4160 KB） |
| work flash | `0x14000000`（128 KB） |
| SRAM | `0x08000000` |
| `WORKAREAADDR`（flash 算法 RAM） | `0x08000800`，32 KB |
| `CPUSS.CM0_CTL` | `0x40201000` |
| `CPUSS.CM0_CLOCK_CTL` | `0x40201008` |
| `CLK_ROOT_SELECT[0]` | `0x40261240` |
| `MPU_CTRL` | `0xE000ED94` |
| `SystemCoreClock` | 变量，看 `.map` 或 `nm`（约 `0x0802069C`） |
| CM0+ 正常运行 PC | `0x10000A06`（`__cy_m0p_code_start`，CM0P_SLEEP） |
| 正常 `SWD DPIDR` | `0x6BA02477` |

**永远不要手算外设频率** —— 用 Device Configurator 的 Clocks 页，
或读 `Cy_SysClk_ClkPeriGetFrequency()`。
