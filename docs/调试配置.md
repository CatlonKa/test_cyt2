# 调试配置（CYT2BL3CAS）

> 烧录见 `docs/编译烧录排障手册.md`。本文只管 **F5 调试 / attach**。

---

## 0. 结论速览

| 探针 | 能否调试 | 原因 |
|---|---|---|
| **J-Link**（`1366:0105`） | ✅ 可行 | SEGGER 在 GDB Server 内自己处理复位重连 |
| CMSIS-DAP / DAPLink（`C251:F001`） | ❌ 不行 | `reset halt` 必关调试域（§2） |
| 逐飞 ZF-WLFS-DAP（`5A46:4101`） | ❌ 不行 | 连 DP 都读不到（手册 §1.1） |
| KitProg3 / MiniProg4 | ✅ 最佳 | 唯一有 test-mode acquire，本机没有 |

**本机唯一可用路线：J-Link + JLinkGDBServerCL + Cortex-Debug。**
> 下文 F5 配置**尚未实跑验证**，属待验证方案。

## 1. 现有 `launch.json` 全是 OpenOCD

2 个配置（`Launch` / `Attach ... (KitProg3_MiniProg4)`）都是 `servertype: "openocd"`，
都走 `openocd.tcl` —— 第一行就写死：

```tcl
source [find interface/kitprog3.cfg]
```

→ **不用 KitProg3 就都跑不起来**。⚠️ 重跑 `make vscode` 会覆盖 `launch.json`，自加条目会丢。

---

## 2. 为什么 DAPLink 调试不通

不是配置问题，是物理限制：

```
调试需要 reset halt
  → T2G 复位走 SYSRESETREQ
  → 复位后调试域（DP）掉电
  → gdb server 拿不回连接
```

OpenOCD 在同一个会话里做不到「复位后重连」，所以 `overrideLaunchCommands` 里那句
`monitor traveo2 reset_halt sysresetreq` 一执行，后面所有调试命令都失效。

J-Link 不同：**SEGGER 自己在 GDB Server 内部处理复位重连**，日志里

```
Reset: Halt core after reset via DEMCR.VC_CORERESET.
Reset: Reset device via AIRCR.SYSRESETREQ.
```

之后仍能继续访问，这是 DAPLink 路线没有的能力。

## 3. J-Link 配置

### 3.1 推荐：Attach + 先烧录

```jsonc
{
    "name": "J-Link: Attach CM4",
    "type": "cortex-debug",
    "request": "attach",
    "cwd": "${workspaceFolder}",
    "executable": "build/last_config/mtb-example-empty-app.elf",
    "servertype": "jlink",
    "device": "CYT2BL3CAS_M4",
    "interface": "swd",
    "serverArgs": ["-speed", "4000"],
    "preLaunchTask": "Program",
    "svdFile": "../mtb_shared/mtb-pdl-cat1/release-v3.25.0/devices/COMPONENT_CAT1A/svd/tviibe4m.svd",
    "liveWatch": { "enabled": true },
    "presentation": { "group": "CM4" },
    "showDevDebugOutput": "none"
}
```

`preLaunchTask: "Program"` 调 `flash.ps1` 用 `_M0` 烧录；GDB Server 只负责连 `_M4` 调试。

### 3.2 不建议 `request: "launch"`

`launch` 下 Cortex-Debug 会自行 `load` 到目标，而 **`_M4` 无法编程 flash**，T2G 上会失败。
要用就改 `device: "CYT2BL3CAS_M0"`（那样只能调 CM0+ 的 `CM0P_SLEEP` 镜像）。

### 3.3 前置条件（已就位）

| 项 | 值 |
|---|---|
| `cortex-debug` 扩展 | `marus25.cortex-debug-1.12.1` |
| `cortex-debug.JLinkGDBServerPath.windows` | `D:/stm32_tools/jlink/JLink_V988/JLinkGDBServerCL.exe` |
| `cortex-debug.armToolchainPath` | `D:/Infineon/Tools/mtb-gcc-arm-eabi/14.2.1/gcc/bin` |
| SVD | `tviibe4m.svd`（1.34 MB） |

⚠️ `JLinkGDBServerPath` 指错 → 报 `gdb-server path not found`，F5 直接起不来。

## 4. ⛔ 双核：`_M0` 才能烧，`_M4` 只能看

| 后缀 | 能看到谁 | 能烧 flash |
|---|---|---|
| `CYT2BL3CAS_M0` | Cortex-M0+ | ✅ **只有它能烧** |
| `CYT2BL3CAS_M4` | Cortex-M4 | ❌ |

所以烧录与调试**必须分两段**（两个独立进程）：

```
preLaunchTask: "Program"              → flash.ps1 用 _M0 烧
        ↓
servertype: "jlink", device: "_M4"    → gdb server 连 M4
```

别看 `numberOfProcessors` / `targetProcessor` —— 那是 **OpenOCD 专用**，jlink 下不生效；
想换核只能改 `device` 重开会话。

CM0+ 正常 PC = `0x10000A06`（`__cy_m0p_code_start`）；停在 `0x0800_xxxx` = 残留 flash 算法，
`0xFFFFFFFE` = Lockup → 见手册 §2.4。

## 5. 验证与故障

### 5.1 起来后确认

| 检查 | 期望 |
|---|---|
| CALL STACK | 有 `main` 帧 |
| `SystemCoreClock` | `160000000`（ECO+PLL 生效） |
| CM4 的 PC | `0x1008xxxx`（flash 区） |
| SVD 视图 | 能展开 `CPUSS` / `SCB0` |

### 5.2 命令行排障（不经 VS Code）

```powershell
# 1) 起 GDB Server（保持这个窗口不关）
& 'D:\stm32_tools\jlink\JLink_V988\JLinkGDBServerCL.exe' `
    -device CYT2BL3CAS_M4 -if SWD -speed 4000 -port 2331 -nogui

# 2) 另开一个终端，用 gdb 连上去读 PC
& 'D:\Infineon\Tools\mtb-gcc-arm-eabi\14.2.1\gcc\bin\arm-none-eabi-gdb.exe' `
    -ex "target remote :2331" -ex "monitor halt" -ex "info registers pc" `
    -ex "detach" -ex "quit" build/last_config/mtb-example-empty-app.elf
```

看到 `Listening on TCP/IP port 2331` + `Waiting for GDB connection...` 就说明 server 侧正常。

---

### 5.3 故障表

| 现象 | 原因 | 解法 |
|---|---|---|
| `gdb-server path not found` | `JLinkGDBServerPath.windows` 路径错 | 指向 `D:/stm32_tools/jlink/JLink_V988/JLinkGDBServerCL.exe` |
| `Could not connect to target` | 探针被占用 | 杀掉别的 JLink/GDB Server；或断电重上电 |
| 烧录成功但停不住 | `device` 写成 `_M0` 却在看 CM4 代码 | 改 `CYT2BL3CAS_M4` |
| 断点是灰的 | elf 与 flash 里的镜像不一致 | 先 `Program` 再调试，别用旧 elf |
| F5 弹 `task ... does not exist` | `preLaunchTask` 名字错 | 只填 `Build` / `Program`（存在的那两个） |
| 重开工程后配置没了 | `make vscode` 覆盖 launch.json | 从本文档复制回去 |

⚠️ **调试期间别烧录**：`flash.ps1` 要独占 J-Link，GDB Server 在跑时会报
`J-Link is already in use`。先 `Shift+F5` 结束会话。
